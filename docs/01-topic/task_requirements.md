## 二、研究目标

设计并实现一个基于 ESP32 的多节点智能环境监测系统，使用 MQTT 协议实现多个节点与服务端之间的数据通信。

重点研究网络异常情况下的数据可靠传输问题，通过断网缓存、自动重连、数据补传及重复消息处理等机制，提高系统在网络不稳定环境下的数据完整性和通信可靠性。

## 三、系统最低功能要求

### 1. 多节点环境监测

- 至少实现 2 个独立节点。
- 节点使用 ESP32 或 Python 模拟实现。
- 支持温度、湿度、光照等环境数据采集。
- 每条数据必须包含 node_id、seq、timestamp。
- 支持多个节点同时向服务端发送数据。

### 2. MQTT 通信

- 部署 MQTT Broker。
- 实现节点 MQTT 客户端连接。
- 实现服务端消息订阅。
- 实现节点与服务端之间的数据传输。
- 实现基本的连接状态监测。

### 3. 服务端与数据库

- 实现 MQTT 消息接收。
- 实现数据解析和合法性校验。
- 建立环境数据存储表。
- 实现历史数据查询。
- 实现基于节点编号和消息序号的数据去重。

### 4. Web 监测平台

- 展示节点在线状态。
- 展示实时环境数据。
- 支持历史数据查询。
- 支持环境异常报警。
- 支持基本远程控制。

### 5. 可靠通信机制

- 实现网络异常检测。
- 实现断网期间 RAM 缓存。
- 实现 MQTT 自动重连。
- 网络恢复后自动补传缓存数据。
- 实现补传确认和缓存清理。
- 避免重复消息造成数据库重复记录。

## 四、可靠通信实验要求

### 1. 断网测试

- 10 秒断网实验，至少 3 轮。
- 30 秒断网实验，至少 3 轮。
- 记录每轮实验的节点数量和数据发送情况。
- 记录断网前后数据完整性。

### 2. 性能指标

| 指标 | 测试内容 |
|---|---|
| 数据完整率 | 实际成功接收的数据与预期数据的比例 |
| 重连时间 | 网络恢复至 MQTT 连接恢复所需时间 |
| 补传成功率 | 成功补传的数据与待补传数据的比例 |
| 端到端时延 | 节点采集数据至服务端接收数据的时间 |
| 通信表现 | 不同节点数量下的通信情况 |

### 3. 实验数据

所有实验需要保留原始记录，包括：

- 节点编号
- 消息序号
- 数据采集时间
- 服务端接收时间
- 网络中断时间
- 网络恢复时间
- 补传成功数量
- 数据完整率
- 平均通信时延
