## 一、研究问题

随着物联网技术的发展，多节点环境监测系统在智慧农业、智慧校园、智能建筑等领域得到了广泛应用。在多节点通信环境下，网络不稳定、通信中断、数据丢失以及节点重新连接后的数据恢复等问题，会影响环境监测系统的数据完整性和运行可靠性。

本课题以 ESP32 为主要硬件平台，设计并实现一个面向多节点物联网的智能环境监测与可靠通信系统，通过 MQTT 协议实现多个环境监测节点与服务端之间的数据传输，并结合断网缓存、自动重连和数据补传机制，提高系统在网络异常情况下的数据传输可靠性。

本课题重点研究以下问题：

1. **多节点数据采集与通信问题：** 如何实现多个 ESP32 节点的独立接入、环境数据采集和统一通信管理？
2. **网络异常与数据丢失问题：** 当节点与服务端之间的网络连接中断时，如何保证采集数据不会直接丢失？
3. **自动重连与数据补传问题：** 网络恢复后，如何实现节点自动重新连接，并将断网期间缓存的数据重新发送至服务端？
4. **数据完整性与通信性能问题：** 如何通过实验评估系统的数据完整率、重连时间、补传成功率和端到端通信时延？
5. **多节点通信性能问题：** 在不同节点数量和通信负载下，系统的消息接收率、通信时延和整体运行表现有何变化？

## 三、拓展目标

在完成最低要求的基础上，根据时间和系统运行情况开展以下拓展工作：

1. **更多节点并发：** 将节点数量扩展至 5 个、10 个，测试不同节点规模下的通信性能。
2. **动态设备管理：** 支持设备注册、设备状态监测、设备信息管理及动态接入。
3. **MQTT QoS 机制比较：** 对 QoS 0、QoS 1、QoS 2 在不同网络条件下的消息传输表现进行比较。
4. **缓存机制优化：** 研究缓存队列管理、数据补传顺序和重复消息处理。
5. **通信性能优化：** 分析节点数量、消息发送频率和网络异常对系统通信性能的影响。

拓展目标不影响基础系统和可靠通信机制的优先完成。

## 四、技术路线

本课题采用 ESP32 多节点采集、MQTT 消息通信、服务端数据处理、数据库存储和 Web 可视化相结合的技术方案。

### 4.1 总体技术流程

```text
       ESP32 节点 1
       环境数据采集
             |
             |
       ESP32 节点 2
       环境数据采集
             |
             v
       MQTT 消息通信
             |
             v
        MQTT Broker
             |
             v
         服务端
      消息接收与处理
             |
             v
         数据库
      实时数据与历史数据
             |
             v
        Web 监测平台
      实时监测 / 历史查询
      报警管理 / 远程控制
```

可靠通信机制贯穿节点与服务端之间的数据传输过程：

```text
正常网络连接
     |
     v
数据采集与 MQTT 发送
     |
     v
检测到网络中断
     |
     v
数据暂存至 RAM 缓存
     |
     v
自动尝试恢复 MQTT 连接
     |
     v
网络连接恢复
     |
     v
缓存数据按序补传
     |
     v
服务端数据校验与重复消息过滤
     |
     v
补传确认与缓存清理
```

### 4.2 计划采用的技术

| 技术 | 主要用途 |
|---|---|
| ESP32 | 多节点环境数据采集与通信 |
| Python | 初期模拟节点及服务端开发 |
| MQTT | 节点与服务端之间的消息通信 |
| Mosquitto | MQTT 消息代理服务 |
| Flask | 服务端接口开发 |
| SQLite | 环境数据及历史记录存储 |
| HTML / CSS / JavaScript | Web 监测界面 |
| ECharts | 环境数据可视化 |
| Git / GitHub | 项目代码管理与版本控制 |

具体技术版本以实际开发环境和依赖配置为准。

### 6.2 核心性能指标

| 指标 | 计算方法 |
|---|---|
| 数据完整率 | 成功接收的数据条数 / 预期产生的数据条数 × 100% |
| 重连时间 | 网络连接恢复时间 - 网络实际恢复时间 |
| 补传成功率 | 成功补传的数据条数 / 待补传的数据条数 × 100% |
| 端到端时延 | 服务端接收时间 - 节点数据采集时间 |
| 消息吞吐量 | 单位时间内成功接收的消息数量 |
